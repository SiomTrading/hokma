Backtest engine (SPEC-020, block H4). Hokma's backtest service runs on the event driven trading engine Nautilus Trader 1.231.0
(copyright Nautech Systems Pty Ltd), published under the GNU Lesser General Public License v3.0 or later (LGPL-3.0-or-later).
The full license text is in the licenses folder of the installed package and at https://www.gnu.org/licenses/lgpl-3.0.txt.
Source code of the library: https://github.com/nautechsystems/nautilus_trader

How Hokma uses it, in line with the license:
- The library is installed as a separate package with pip and is never modified: no file of the library is edited, copied or
  redistributed inside Hokma. The student can replace it with another version of the same library at any time.
- Everything that changes its behavior lives in Hokma's own code (backend/hokma/backtest/): the order of the ticks of a bar, the fill
  rules, the costs and the switch-off in memory of its portfolio statistics. None of that code is a copy of the library.
- Only one Hokma file imports the library (backend/hokma/backtest/_lib.py); the rest of Hokma reaches it through that wrapper.

Brand rule: the name of the engine is not used in the interface of Hokma, in the kit or in any text the student reads. It appears
only in pyproject.toml, uv.lock, backend/hokma/backtest/_lib.py and in this folder; scripts/check_repo_rules.py fails otherwise.

Broker commission tables (SPEC-020, L-16 and L-17: backend/hokma/broker/fees/). The amounts are public prices of each broker (per contract, per share, per order or a share of the value). They were read from
the fee models of the Lean project (Apache-2.0), which cite the public price list of each broker; no code of that project is used, and the tables are plain data in Hokma's own JSON format. Each table
says in its header the source and the date it was read (2026-11-22), that it was not yet checked against a real statement, and which parts of the price list it leaves out. Interactive Brokers futures, stocks, options and CFDs:
ibkr_futures, ibkr_micro_futures, ibkr_stocks, ibkr_options and ibkr_cfd. Alpaca (stocks, options and crypto), Coinbase Advanced and Kraken Pro (crypto), Tastytrade and TradeStation: one table each.

Derivative pricing (SVC-options, SPEC-019 block B1; recipe in docs/quant/options-pricing.md). The recipe and the code are Hokma's own; nothing is copied.
The models follow their published papers, cited here as the origin of the formulas: Black and Scholes (1973) and Merton (1973) for the option price with a
dividend yield; Garman and Kohlhagen (1983) for currency options; Cox, Ross and Rubinstein (1979), Jarrow and Rudd (1983), Tian (1993) and Leisen and Reimer
(1996) for the binomial trees; Bjerksund and Stensland (2002) for the American approximation; Reiner and Rubinstein (1991) for barrier options and
Kemna and Vorst (1990) for the geometric average price option; Breeden and Litzenberger (1978) for the risk-neutral density; Gatheral (2004) for the SVI smile.
The pricing libraries FinancePy, tf-quant-finance and the QuantLib bindings were read only for the idea of which model fits which style of option; no code, data or asset of them is included or loaded.

Replication statistics (SPEC-019 block B9, rule "realistic expectations" of the desk judge). The rule text is Hokma's own; nothing is copied.
The figures it quotes (a median Sharpe ratio of 0.37 and 48 percent of results with a t statistic above 1.96, out of 4,843 academic papers coded and run) are

Hokma uses them only as a prior for the judge, never as a threshold.
